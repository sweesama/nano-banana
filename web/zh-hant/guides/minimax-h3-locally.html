如何在本機運行 MiniMax H3

MiniMax H3 可以是你自己機器上的開源 H3-Base 影片權重，也可以是 MiniMax 的託管 API。這是兩套系統。下面的硬件說明只談影片這條邊界。後文單獨寫靜態圖像模型 MiniMax-H3-Image 的託管介面。本站沒有對兩者做過基準測試。

nano-banana.live 不是 MiniMax 的網站，不分發 H3 權重，也沒有測過 H3。下面的數字轉錄自 MiniMax 的模型卡、倉庫和本機部署指南，2026 年 10 月 22 日重讀。部署指南自己寫的最後審閱日期是 2026 年 8 月 26 日。買硬件或鎖定某個 commit 之前，請再打開那些頁面看一遍。

本機客戶端不等於本機推論

MiniMax-H3 模型卡列出兩種使用完整產品的託管方式：Open Platform API（全球用 platform.minimax.io，中國用 platform.minimaxi.com），以及 Hailuo 應用程式（hailuoai.video 和 hailuoai.com）。筆記本上的 Python 腳本去調這些地址，只是客戶端。模型仍跑在 MiniMax 的服務上。

真正的本機推論，是開源權重在你控制的機器上執行。同一張模型卡說，完整的 H3 系統有三個模組，開源發佈裡只有其中一個：

  • H3-Context-IR 把自由形式的多模態指令收成結構化表示。MiniMax 說它依賴託管模型，不在開源發佈裡。
  • H3-Base 生成 768p 影片，並帶同步立體聲。這是你可以下載的部分。
  • H3-Regenerate-2K 用 768p 輸出和原始上下文再生成 2K 結果。MiniMax 說這個模組尚未開源。模型卡上的「2K」指的是這一步託管處理，不是本機 checkpoint 上的一個開關。

MiniMax 的本機部署指南把後果寫得很直接：自建的 H3-Base 服務重現不了平台上完整的 Context-IR 和 2K 流程。模型卡上的「完整 2K 工作流」是本機 SGLang 進程再加上那兩個託管 API。這種混用不是離線。

開源發佈裡有什麼

模型卡和 MiniMax-H3 倉庫描述了兩個任務 checkpoint。兩者都是經過 CFG 蒸餾的 Omni Transformer 權重，隨附 processor、tokenizer、文本編碼器、視覺 VAE 和音訊 VAE。

Checkpoint任務輸入輸出
H3-Base FL2VA t2va 文生有聲影片，以及 fl2va 首尾幀生有聲影片 文本。可選首幀、尾幀，或兩者都給。 影片和音訊，BF16
H3-Base Ref2VA ref2va 參考生有聲影片 文本，加上參考圖像、影片和/或音訊。模型卡的上限是 9 張圖、3 段影片、3 段音訊，合計最多 12 個檔案。每段 2–15 秒，每種模態的總時長最多 15 秒。 影片和音訊，BF16

同一天核對的輸出約定是：4–15 秒，短邊預設 768 像素，24 FPS，32 kHz 立體聲。點名的長寬比包括 21:9、16:9、4:3、1:1、3:4 和 9:16。對白穩定支援阿拉伯語、中文、英語、法語、德語、意大利語、日語、韓語、葡萄牙語、俄語和西班牙語。FL2VA 和 Ref2VA 不能互換：部署指南說，FL2VA 服務不會提供 ref2va。

架構上，模型卡說 H3-Omni-Transformer 是 330 億參數的稠密模型，其中約 130 億在 AdaLN 分支裡，只做推論時不必載入。文本編碼器使用完整的 Qwen3-VL-32B 權重，讀取第 50 層的隱藏狀態。這些是參數量，不是測出來的顯示記憶體下限。

權重使用 MiniMax H3 Community License Agreement。模型卡和倉庫裡的許可文本，才是地域、商用和可接受用途的依據。本頁不轉述那些條款。

怎樣在本機運行 MiniMax H3

模型卡點了四個推論框架，各自有指南：SGLang、vLLM、Diffusers 和 ComfyUI。MiniMax 的部署指南最後審閱於 2026 年 8 月 26 日，分成視覺化的 ComfyUI 路徑，和鎖定版本的 SGLang 服務。它把 vLLM-Omni 配方視為社群維護，而不是該頁可重現的基線。

工作站上的 ComfyUI

這是部署指南為互動式本機使用推薦的路徑。它仍然只對 ComfyUI 下載的轉換後權重做本機推論。檔案來自 Comfy-Org/MiniMax-H3，包括 INT8 和 NVFP4 組件。MiniMax 說它們和官方的混合 BF16/FP32 checkpoint 不是同一套數值基線，顯示記憶體和畫質都可以不同。

指南審閱過的基線是 ComfyUI 0.30.0 或更新版本，內置 T2V、I2V 和 R2V 模板。它也說，這份 ComfyUI 指南沒有公佈最低顯示記憶體。列出的步驟是：

  1. 把 ComfyUI 更新到 0.30.0 或更新，然後啟動。
  2. 打開 Template Library，再打開 Video。
  3. 選擇 MiniMax H3 的 T2V、I2V 或 R2V。T2V 和 I2V 用 FL2VA 擴散模型。R2V 用單獨的 Ref2VA 模型。
  4. 讓模型掃描彈出視窗下載模板要求的檔案。模型列表沒刷新就重啟 ComfyUI。
  5. 填寫提示詞，以及需要的圖像、影片或音訊參考。I2V 接收一張輸入圖，可選首幀和尾幀。
  6. 在 Resolution Selector 裡用 0.98 百萬像素，邊長為 32 的倍數，或直接設 1344×768。指南說不要用 1.0 百萬像素那一檔，因為它會落到 1376×768，超過 H3-Base 768×1344 的像素面積上限。
  7. 把工作流加入佇列。文檔中的結果是一段 MP4：24 FPS 影片串流，加上同步立體聲。

時長會對齊到模型在 24 FPS 下的 17k + 5 幀網格，所以你填的長度可能被挪到合法幀數。示例 FL2VA 工作流用 20 步，另有可選的 8 步 Turbo LoRA，指南說它可能降低動作和音訊質素。對比輸出時把 LoRA 記下來。

用 SGLang 自建 API

模型卡上的 FL2VA 短示例是一條四卡啟動命令。它沒有寫 GPU 型號：

sglang serve \
  --model-path MiniMaxAI/MiniMax-H3 \
  --num-gpus 4 \
  --ulysses-degree 4 \
  --performance-mode speed \
  --host 0.0.0.0 \
  --port 30010 \
  --model-variant fl2va

這個 host 參數要看仔細。部署指南鎖定的快速入門綁定的是 127.0.0.1，並且說，在把綁定改成 0.0.0.0 之前，要先在連接埠前面放上認證、TLS、配額，以及授權所要求的託管服務防護。把模型卡上的命令直接暴露到公網，不是指南的基線。

同一份指南可重現的基線（審閱於 2026 年 8 月 26 日）比「裝上 SGLang 就能跑」窄得多：

  • 模型 MiniMaxAI/MiniMax-H3，修訂 42ed227ee7df40d41602854ae760620d6eb651fe。
  • SGLang 原始碼提交 2511743bd784e69e5a81ca3d926a000711dae4ab。該頁說 H3 支援從 SGLang v0.5.17 起隨 PyPI 提供，擴散安裝仍要加 --prerelease=allow。它也說，H3 擴散服務還不是穩定的 SGLang 發佈契約。
  • 只下載你要服務的那一份。FL2VA 是 model_index.json 加上 FL2VA/*。--model-path 保持倉庫根目錄，用 --model-variant fl2va 選擇分區。不要把伺服器指到 FL2VA/ 子目錄。
  • 快速入門的硬件一行是：單機 8 張 NVIDIA B200，Ulysses 度數 8，組件常駐。該頁稱這是參考配置，不是最低配置。
  • 就緒的標誌是 /health 返回 {"status":"ok"}。/liveness 只說明 HTTP 進程仍在運行。

模型卡上單個任務族的下載命令是：

hf download MiniMaxAI/MiniMax-H3 --include "model_index.json" "FL2VA/*" --local-dir MiniMax-H3

對完全離線的機器，部署指南說：在能聯網的電腦上下載，複製目錄，確認 model_index.json 和所選的 FL2VA/ 或 Ref2VA/ 都在，再用 HF_HUB_OFFLINE=1 啟動。文中提到中國大陸鏡像 MiniMax/MiniMax-H3，並說它和鎖定的 Hugging Face 提交是否修訂一致尚未記錄，所以鎖定的基線不用這個鏡像。

模型卡也指向 Diffusers 和一份 vLLM 配方。Diffusers 是同一套 Hugging Face 倉庫的載入器，不是第二個模型。MiniMax 部署頁上的 vLLM-Omni 一節標為實驗性、由社群維護。兩者都不會把託管的 Context-IR 或 2K 模組變成本機程式碼。

硬件和系統要求

2026 年 10 月 22 日讀過的材料裡，沒有單一的「最低電腦配置」。部署指南說，沒有公佈的要求，不等於沒有要求。用和你實際安裝路徑對應的那一行。

如果公佈的多卡形態裝不進你現有的電腦，租來的機器仍然是遠端硬件。本站的雲 GPU 指南談的是為圖像 checkpoint 規劃租賃。它沒有補上一個 H3 顯示記憶體數字，租賃也不會讓 H3-Context-IR 或 H3-Regenerate-2K 變成本機的。

MiniMax H3 和託管 API

有用的比較是系統邊界，不是質素排名。本站沒有做過並排測試。

  • 託管 API 或 Hailuo 應用程式。請求發給 MiniMax。完整棧可以包含 Context-IR 和 2K 再生。你不安裝權重。推論不在本機。
  • 本機 H3-Base。你下載 FL2VA、Ref2VA 或兩者，用 SGLang、vLLM、Diffusers，或 Comfy-Org 的轉換權重來跑。除非事後再調託管的 2K API，輸出停在上面的 768p 約定裡。
  • Comfy-Org 權重和官方 checkpoint。兩者都可以在你的機器上跑。MiniMax 說它們是不同產物。不要把兩邊的基準數字混在一起。

本站已經寫過的圖像模型是另一項任務，不能當作 H3 的替代 checkpoint。FLUX.1-dev、HiDream-O1-Image、Z-Image、Qwen-Image-Edit-2511 和 HunyuanImage 3.0 生成或編輯靜態圖像。它們不實現 H3 的 fl2va 有聲影片任務。這裡不聲稱這些模型和 H3 之間的延遲或偏好分數。這些指南目前是英文。

官方 skill 裡的提示詞結構

MiniMax 在 H3 倉庫裡放了一份寫提示詞的 skill。它是格式指南，不是測出來的質素分數。對基礎模式，skill 要求按這個順序保留三個欄位：integrated_multimodal_description、overall_soundscape，然後是 non_diegetic_music。它點名的模式是：

  • T2VA：從文本搭出視聽時間線。
  • I2VA：從首幀出發往前走。
  • FL2VA：描述首幀和尾幀之間的連續路徑。
  • L2VA：推斷一個合理的開場，落到給定的尾幀上。

Ref2VA 是另一套六段改寫：subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape 和 non_diegetic_music。skill 說改寫用英文寫，對白和畫面文字保留原文，描述要匹配所請求的時長（4–15 秒），並寫明關鍵幀怎樣接到時間線上。完整模板是該 skill 旁邊的 references/base-en.txt 和 references/ref-en.txt。本頁不另加提示詞。

首幀和尾幀

FL2VA 是做這件事的本機 checkpoint。模型卡說：零張圖是文字生成影片，一張圖是首幀或尾幀條件，兩張圖是首尾幀生成。部署指南把同一件事映射到 SGLang 任務 fl2va，一到兩個角色為 keyframe 的圖像條件，以及 ComfyUI 的 I2V 模板。

本站不能做這次生成。如果你已經有一段影片，只需要把頭尾存成圖片檔案，首尾幀影片頁面在瀏覽器裡提取。它不調用 MiniMax。該頁目前是英文。

通過託管 API 使用 MiniMax-H3-Image

MiniMax-H3-Image 是靜態圖像模型：文生圖和圖像編輯。它不是 H3-Base 影片 checkpoint，調用託管圖像 API 也不是本機推論。這一節的事實在 2026 年 11 月 12 日讀自 MiniMax 的 API 參考、定價頁，以及 MiniMax-H3-Image 模型卡。Google 的圖像價格同一天讀自 Gemini 定價頁。

端點和 API 密鑰

模型卡寫了兩個主機。全球請求用 https://api.minimax.io。同一張卡上的中國主機是 https://api.minimax.cn。文生圖是 POST /v1/images/generations。圖像編輯（1 到 16 張參考圖）是 POST /v1/images/edits。兩者都接受 MiniMax-H3-Image 和 MiniMax-H3-Image-Highspeed。OpenAPI 的安全方案是 Authorization: Bearer 加上 API 密鑰。

MiniMax 的準備指南說，先在 API 平台註冊或登入，再打開 API Keys，為按量計費選擇 “Create new secret key”。該指南說按量計費涵蓋圖像模型。密鑰是憑證：API FAQ說不要分享它，也不要放進瀏覽器或其他客戶端程式碼。把它放在環境變數裡，例如 MINIMAX_API_KEY。M Plan 用另一把訂閱密鑰，不要把兩把鑰匙當成可以互換。按量計費從帳戶餘額扣款。本站不簽發 MiniMax 密鑰，也不給帳戶充值。

生成介面的參考說伺服器最多等 600 秒，所以客戶端超時至少要這麼長。這個端點不是冪等的：請求發出之後，即使客戶端斷開，MiniMax 仍會做完生成，並對成功的圖像收費；重試會再生成一次、再收一次費。

一次基本的文生圖請求

參考把 model 和 prompt 標為必填。n 預設是 1。下面的請求體用文檔示例裡的提示詞和 2720x1536 尺寸，一張圖，響應為 URL。除了已經在環境裡的密鑰，不要替換別的內容。

curl --max-time 600 https://api.minimax.io/v1/images/generations \
  -H "Authorization: Bearer $MINIMAX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "MiniMax-H3-Image",
    "prompt": "An orange cat lying on a windowsill basking in the sun, warm afternoon light, film texture",
    "size": "2720x1536",
    "n": 1,
    "response_format": "url"
  }'

中國主機把源換成 https://api.minimax.cn，路徑不變。圖像 URL 要自己下載；參考說這個 URL 不保證一直可用。編輯走另一條路徑，文檔是分開的。

價格：託管 API、本機權重和 Nano Banana

自己跑權重，在模型卡和那張定價頁上都沒有一個美元單價。模型卡列出圖像倉庫 68.65 GB，其中 DiT 檔案 66.28 GB，圖像 VAE 2.34 GB，另外還要從 MiniMaxAI/MiniMax-H3 而不是圖像倉庫載入 66.7 GB 的文本編碼器。可選的提示詞擴展器列為 17.9 GB。這些是下載體積。MiniMax 沒有公佈電費、顯示卡購買價或本機的單張成本，本頁也不編一個。租來的 GPU 是第三張帳單，由租賃商開，而且仍然是遠端硬件。

Google 的 Gemini API 定價同一天閱讀，Nano Banana 同樣按 token 計價，並印出圖像輸出的等價金額。那和 MiniMax 示例裡的合計不是同一種數。標準 gemini-nano-banana-2.1（Nano Banana 2.1）的免費層標為不可用。文本、圖像和影片輸入是每百萬 token 1.50 美元。圖像輸出是每百萬 token 30 美元，腳註把它換算成 1K 圖像 0.0336 美元（1024×1024，1120 token）、2K 0.0504 美元（2048×2048，1680 token）、4K 0.113 美元（4096×4096，3780 token）。文本和思考輸出另按每百萬 token 7.50 美元計。同一腳註把 Batch 圖像輸出標為每百萬 token 15 美元。這些單張數字是圖像輸出的等價額。輸入 token，以及任何搜尋接地，都另算。

Nano Banana 2，即 gemini-3.1-flash-image，是另一行。它的標準圖像輸出是每百萬 token 60 美元：腳註換算為 1K 0.067 美元、2K 0.101 美元、4K 0.151 美元，文本或圖像輸入為每百萬 token 0.50 美元，免費層同樣標為不可用。本站英文概覽說，截至 2026 年 10 月 9 日的核對，Google 建議新項目用 Nano Banana 2.1。這是選型說明，不是說 2.1 和 Nano Banana 2 同價。

不要用 MiniMax 的 0.02179 美元示例去減 Google 的 0.0336 美元圖像輸出口徑，然後把差額叫作省下來的錢。一個是 MiniMax 對示例提示詞的示意合計。另一個是 Google 在計入輸入之前的圖像輸出 token 價格。確切的模型 ID、解像度和你要發送的提示詞，以廠商頁面為準。
