Gemini image API: Editing Images with Python using Nano Banana

Step‑by‑step guide to edit images with the Gemini image API using Python and the Nano Banana client, including setup, code examples, and troubleshooting.

Prerequisites and Setup

To begin editing images with the Gemini image API, you need a Python environment, the official Google GenAI client, and the Pillow library for image handling. The Nano Banana client (nano_api.py) provides a thin wrapper that sends a local image and an editing prompt to Google’s hosted gemini-3.1-flash-image model.

  1. Install the required packages:
    2. pip install google-genai pillow
  2. Obtain a Google API key. You can create one in Google AI Studio or the Cloud Console. Set it as an environment variable named GOOGLE_API_KEY or GEMINI_API_KEY.
  3. Prepare an input image (e.g., reference.jpg) in the same directory where you will run the script.

For a quick walkthrough of environment setup, see our quickstart guide. If you prefer to run the Nano Banana client locally without relying on external services, refer to the local execution guide.

Understanding the Nano Banana API client

The Nano Banana client is not a model that runs on your machine; it is a Python script that forwards your request to Google’s cloud‑based Gemini image model. The script (nano_api.py) performs the following steps:

  • Loads the API key from the environment.
  • Opens the input image with Pillow.
  • Creates a genai.Client instance.
  • Calls client.models.generate_content with the model identifier gemini-3.1-flash-image, a text prompt, and the image.
  • Iterates over the response parts, extracts any inline image data, saves it to a file, and prints status messages.

Because the heavy lifting happens on Google’s servers, you do not need a GPU or specialized hardware to use this API. The client merely handles authentication, request formatting, and response parsing.

Step‑by‑step: Editing an image with Gemini image API

Below is a concrete example that demonstrates how to replace the background of a portrait while keeping the subject’s lighting and pose intact. The code follows the structure shown in nano_api.py [2].

1. Load the input image

First, verify that the file exists and open it with Pillow:

from pathlib import Path
from PIL import Image

def load_image(path: str) -> Image.Image:
    p = Path(path)
    if not p.is_file():
        raise FileNotFoundError(f"Input image not found: {path}" )
    return Image.open(p)

2. Construct the editing prompt

The prompt should describe the desired change in natural language. For background replacement, a clear instruction works well:

prompt = "Replace the background with a neon cyberpunk city while preserving the subject\'s lighting and pose."

You can experiment with different phrasing; the model interprets the prompt in conjunction with the visual content.

3. Call the generate_content method

Initialize the GenAI client with your API key, then send the prompt and image:

import os
from google import genai

def edit_image(input_path: str, prompt: str, output_path: str = "output.png"):
    api_key = os.getenv("GOOGLE_API_KEY\)) or os.getenv("GEMINI_API_KEY\)
    if not api_key:
        raise RuntimeError("Set GOOGLE_API_KEY or GEMINI_API_KEY before running this script." )
    
    image = load_image(input_path)
    print(f"[*] Loading image: {input_path}" )
    print("[*] Sending image to Nano Banana (Gemini 3.1 Flash Image)..." )
    print(f" Prompt: {prompt}" )
    
    client = genai.Client(api_key=api_key)
    response = client.models.generate_content(
        model="gemini-3.1-flash-image",
        contents=[prompt, image]
    )
    
    for part in response.candidates[0].content.parts:
        if part.text:
            print(part.text)
        elif part.inline_data:
            edited_image = part.as_image()
            edited_image.save(output_path)
            print(f"[+] Success! Edited image saved to: {output_path}" )
            return
    print("[!] No image returned. Check the prompt and safety filters." )

4. Handle the response and save result

The function above prints any text returned by the model (useful for debugging) and, when an inline image is present, saves it as output.png. If the model returns no image, the script warns you to verify the prompt or check whether safety filters blocked the request.

To run the script from the command line, add the following block at the end of your file:

if __name__ == "__main__":
    edit_image(
        input_path="reference.jpg",
        prompt="Replace the background with a neon cyberpunk city while preserving the subject\'s lighting and pose." ,
        output_path="nano_edit_result.png"
    )

Executing python nano_api.py will produce nano_edit_result.png in the same directory.

Common pitfalls and troubleshooting

  • Missing API key: The script raises a RuntimeError if neither GOOGLE_API_KEY nor GEMINI_API_KEY is set. Double‑check your environment variables.
  • File not found: Ensure the path you pass to edit_image points to an existing image file.
  • No image returned: The model may refuse to edit the image due to safety policies or an ambiguous prompt. Try re‑phrasing the instruction or using a simpler edit (e.g., "Change the sky to sunset\)).
  • API errors: Network issues or quota limits will surface as exceptions caught by the except Exception as e block. Consult the Gemini API documentation for error codes and retry strategies.

For a deeper dive into error handling, see the FAQ page, which covers typical API errors and how to interpret them.

When to use the cloud API vs local open‑weight models

The Nano Banana client accesses a cloud‑hosted model (gemini-3.1-flash-image) that requires an internet connection and a valid API key. This approach offers:

  • Zero local compute overhead – no GPU needed.
  • Access to Google’s latest image generation checkpoints.
  • Automatic updates and safety filtering.

If you prefer to run a model entirely on your own hardware, you would need to download an open‑weight image model (e.g., a Stable Diffusion variant) and manage inference locally. The Nano Banana repository does not provide such weights; it is specifically a client for the Gemini image API.

Thus, choose the cloud API when you want quick setup, minimal maintenance, and access to Google’s proprietary models. Opt for a local open‑weight solution only if you have strict data‑privacy requirements or wish to avoid recurring API costs.
