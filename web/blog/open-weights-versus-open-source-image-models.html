Open Weights vs Open Source: Choosing a local AI image model

Open weights and open source are not the same thing. Learn how the OSI definition applies to image models, then compare HunyuanImage and Qwen Image as local options.

If you are comparing a local AI image model for offline generation, the first decision is not which checkpoint looks best in a gallery — it is what you actually receive when you download it. "Open weights" and "open source" are used interchangeably in blog posts, but the Open Source Initiative draws a hard line between them in the Open Source AI Definition 1.0. That distinction determines whether you can inspect training data, retrain the model, or only run the weights someone else published. This article explains the difference, then walks through what it means for HunyuanImage local and Qwen Image local installation.

What "open source" requires under OSAID 1.0

The OSI definition grants four freedoms: use the system for any purpose, study how it works and inspect its components, modify it for any purpose (including changing its output), and share it with or without modifications. Those freedoms apply to a full system and to discrete elements such as a model, weights, or parameters.

The critical part is the "preferred form to make modifications." For a machine-learning system, the OSI says that form must include three things:

  • Data information — enough detail about the training data that a skilled person can build a substantially equivalent system, including provenance, scope, characteristics, how data was obtained and selected, labeling procedures, and filtering methods.
  • Code — the complete source code used to train and run the system, covering data processing, training arguments and settings, validation, tokenizers, hyperparameter search, inference code, and model architecture.
  • Parameters — the weights and other configuration settings, potentially including intermediate checkpoints and the final optimizer state.

The definition is explicit that "Open Source models" and "Open Source weights" must include the data information and code used to derive those parameters. A repository that ships a .safetensors file and an inference script but no training data disclosure is, by this standard, open weights — not open source.

The OSI also notes it does not require a specific legal mechanism for keeping parameters freely available, and expects the legal picture to become clearer over time. In practice, that means you should read the model card and license for each checkpoint rather than assuming a family-wide rule. The Nano Banana FAQ makes the same point about commercial use: do not assume one model family's license applies to every checkpoint, LoRA, demo, or hosted service.

Why the distinction matters when you install locally

For most people running a local AI image model, the practical difference shows up in three places.

1. Reproducibility and provenance

If the training data description is missing, you cannot verify what the model learned from, and you cannot rebuild it. That is a provenance gap, not just a licensing technicality. When a model card omits data information, treat the model as open weights and label it that way in your own notes.

2. Modification rights

Fine-tuning, distillation, and architecture changes require the code and the parameters. If only weights are published, you can run inference and often train adapters, but you cannot reproduce the original training run. Whether that matters depends on your goal: inference-only workflows rarely need the full training stack.

3. Hardware planning

Neither label tells you how much VRAM you need. That depends on the checkpoint, precision, resolution, and your runtime. The hardware requirements guide is referenced by the FAQ as the place to look for alternative offline models such as Z-Image, Qwen-Image, and HunyuanImage. The benchmarks page presents Elo ratings with 95% confidence intervals and notes that unavailable metadata is omitted rather than shown as an empty column.

Comparing HunyuanImage and Qwen Image for local use

The Nano Banana FAQ points readers who need a fully offline solution toward alternatives such as Z-Image, Qwen-Image, and HunyuanImage, and recommends Qwen-Image-Edit-2511 or HunyuanImage 3.0 in the Quickstart Guide for offline image generation. Here is how to think about the comparison without inventing specs the sources do not confirm.

  • HunyuanImage local — named in the FAQ as an open-weight alternative. Exact specifications depend on the checkpoint, precision, and resolution; check the model card rather than a forum post.
  • Qwen Image local — also named in the FAQ as an open-weight alternative, and includes editing-oriented checkpoints such as Qwen-Image-Edit-2511. Qwen Image requirements likewise vary by checkpoint and quantization.

Neither of these should be described as "open source" unless the publisher actually provides data information and training code. The honest label for most downloadable image checkpoints today is open weights image models.

How to check a checkpoint before you install it

  1. Open the model card. Look for a training data section, not just a usage example.
  2. Find the license file. Check whether it is an OSI-approved license or a custom community license.
  3. Look for training code. Inference code alone does not satisfy the OSAID preferred form.
  4. Note the checkpoint name and date. Licenses can differ between versions of the same family.
  5. Estimate your VRAM. Test at low resolution first, and check the model card for the checkpoint you plan to run.
  6. Follow the Quickstart Guide. The FAQ links to the Quickstart Guide for offline image generation recommendations such as Qwen-Image-Edit-2511 and HunyuanImage 3.0.

If a step is missing from the evidence — for example, an exact specification for a specific quantization — say so and link the model card instead of guessing. The Nano Banana FAQ is careful about this: it labels missing inputs or parameters rather than calling an incomplete comparison reproducible. The benchmarks page takes a similar approach by not inferring a model's license, local availability, privacy, or total operating cost when those fields are absent.

Cloud APIs are not local models

One clarification that comes up constantly: running a Python client on your laptop does not make a hosted model local. The Nano Banana FAQ states plainly that Nano Banana 2 cannot be downloaded or run offline, and that a local client still sends the image and prompt to Google's hosted Gemini API. The same logic applies to ChatGPT Image 2 — calling an API from local code is not local inference. If your requirement is a 100% offline, air-gapped workflow, you need open-weight checkpoints, not an API wrapper.

Reading rankings without over-claiming

The Nano Banana benchmarks page sources its leaderboards from Artificial Analysis and refreshes on a scheduled sync. The page shows Elo ratings alongside 95% confidence intervals, and it notes that samples, release dates, and pricing are displayed only when Artificial Analysis returns those fields — unavailable metadata is omitted instead of shown as an empty column. Because snapshots change, treat any single Elo number as a dated observation, not a permanent fact. The Nano Banana FAQ separately warns that hosted models can change and that both hosted and local inference may be nondeterministic across runs or hardware. When you compare a local AI image model against a hosted one, compare the exact workflow you plan to use — same prompt, same resolution, same settings — rather than a headline score.

The short version

Open weights give you parameters you can run and often fine-tune. Open source, under OSAID 1.0, additionally requires data information and the code used to derive those parameters. Most downloadable image checkpoints are open weights. Before installing HunyuanImage or Qwen Image locally, read the model card and confirm the license for that exact checkpoint. If you need a fully offline pipeline, choose an open-weight checkpoint and verify its provenance — and never describe an API client as local inference.
