How to Run MiniMax H3 Locally

MiniMax H3 can run as open H3-Base video weights on hardware you control, or as a hosted MiniMax API. Those are different systems. The hardware notes below stay on that video boundary. A later section covers the separate still-image model, MiniMax-H3-Image, through the hosted API. This site has not benchmarked either one.

nano-banana.live is not a MiniMax site, does not distribute H3 weights, and has not benchmarked H3. Figures below are transcribed from MiniMax's model card, repository, and local-deploy guide, re-read on October 22, 2026. The deploy guide itself says it was last reviewed on August 26, 2026. Re-check those pages before you buy hardware or pin a commit.

A local client is not local inference

The MiniMax-H3 model card lists two hosted ways to use the full product: the Open Platform API at platform.minimax.io (global) or platform.minimaxi.com (China), and the Hailuo apps at hailuoai.video and hailuoai.com. A Python script on your laptop that calls those endpoints is a client. The model still runs on MiniMax's service.

True local inference means the open weights execute on a machine you control. The same card says the complete H3 system has three modules, and only one of them is in the open release:

  • H3-Context-IR turns free-form multimodal instructions into a structured representation. MiniMax says it depends on hosted models and is not in the open-source release.
  • H3-Base generates 768p video with synchronized stereo audio. This is the part you can download.
  • H3-Regenerate-2K regenerates a 2K result from the 768p output and the original context. MiniMax says this module is not open-sourced yet. The card's "2K" line is this hosted step, not a flag on the local checkpoint.

MiniMax's local-deploy guide states the consequence directly: a self-hosted H3-Base service does not reproduce the complete platform Context-IR and 2K workflow. The "Full 2K workflow" on the model card mixes a local SGLang process with those two hosted APIs. That mix is not offline.

What the open release contains

The model card and the MiniMax-H3 repository describe two task checkpoints. Both are CFG-distilled Omni Transformer weights, shipped with a processor, tokenizer, text encoder, visual VAE, and audio VAE.

CheckpointTasksInputsOutput
H3-Base FL2VA t2va text-to-audio-video, and fl2va first/last-frame-to-audio-video Text. Optionally a first frame, a last frame, or both. Video and audio, BF16
H3-Base Ref2VA ref2va reference-to-audio-video Text plus reference images, videos, and/or audio. The card caps this at 9 images, 3 video clips, and 3 audio clips, with at most 12 files combined. Each clip is 2–15 seconds, and the combined duration of each modality is at most 15 seconds. Video and audio, BF16

The card's published output contract, checked the same day, is 4–15 seconds, a short side of 768 pixels by default, 24 FPS, and 32 kHz stereo. Aspect ratios it names include 21:9, 16:9, 4:3, 1:1, 3:4, and 9:16. Dialogue has stable support for Arabic, Chinese, English, French, German, Italian, Japanese, Korean, Portuguese, Russian, and Spanish. FL2VA and Ref2VA are not interchangeable: the deploy guide says an FL2VA server will not serve ref2va.

On architecture, the card says H3-Omni-Transformer is a 33B-parameter dense model, with about 13B of those parameters in AdaLN branches that do not need to be loaded for inference-only deployment. The text encoder uses the full Qwen3-VL-32B weights and reads hidden states from layer 50. Those are parameter counts, not a measured VRAM minimum.

The weights are under the MiniMax H3 Community License Agreement. The license text on the model card and in the repository is the authority for territory, commercial use, and acceptable use. This page does not restate those terms.

How to run MiniMax H3 locally

The model card names four inference frameworks and points each one at its own guide: SGLang, vLLM, Diffusers, and ComfyUI. MiniMax's deploy guide, last reviewed August 26, 2026, splits them into a visual ComfyUI path and a pinned SGLang service. It treats the vLLM-Omni recipe as community-maintained, not as that page's reproducible baseline.

ComfyUI on a workstation

This is the path the deploy guide recommends for interactive local use. It is still local inference only for the converted weights ComfyUI downloads. Those files come from Comfy-Org/MiniMax-H3, including INT8 and NVFP4 components. MiniMax says they are not the same numerical baseline as the official mixed BF16/FP32 checkpoint, so memory and quality can differ.

The guide's reviewed baseline is ComfyUI 0.30.0 or later, with built-in T2V, I2V, and R2V templates. It also says a minimum GPU memory figure is not published for that ComfyUI guide. The steps it lists are:

  1. Update ComfyUI to 0.30.0 or later and start it.
  2. Open Template Library, then Video.
  3. Choose MiniMax H3 T2V, I2V, or R2V. T2V and I2V use the FL2VA diffusion model. R2V uses the separate Ref2VA model.
  4. Let the model-scan pop-up download the files the template asks for. Restart ComfyUI if the model list does not refresh.
  5. Set the prompt and any image, video, or audio references. I2V takes an input image, with optional first and last frames.
  6. In Resolution Selector, use 0.98 megapixels with dimensions that are multiples of 32, or set 1344×768 directly. The guide says not to use the 1.0 megapixel step, because it resolves to 1376×768, above the H3-Base 768×1344 pixel-area limit.
  7. Queue the workflow. The documented result is an MP4 with a 24 FPS video stream and synchronized stereo audio.

Duration snaps to the model's 17k + 5 frame grid at 24 FPS, so a requested length can move to a legal frame count. The example FL2VA workflow uses 20 steps, with an optional 8-step Turbo LoRA that the guide says can reduce motion and audio quality. Record the LoRA if you compare outputs.

SGLang for a self-hosted API

The model card's short FL2VA example is a four-GPU serve command. It does not name the GPU:

sglang serve \
  --model-path MiniMaxAI/MiniMax-H3 \
  --num-gpus 4 \
  --ulysses-degree 4 \
  --performance-mode speed \
  --host 0.0.0.0 \
  --port 30010 \
  --model-variant fl2va

Read that host flag carefully. The deploy guide's pinned quickstart binds 127.0.0.1 instead, and it says to put authentication, TLS, quotas, and the license's hosted-service safeguards in front of the port before anyone changes the bind to 0.0.0.0. Copying the model-card command onto a public interface is not the guide's baseline.

The same guide's reproducible baseline, reviewed August 26, 2026, is narrower than "install SGLang and go":

  • Model MiniMaxAI/MiniMax-H3 at revision 42ed227ee7df40d41602854ae760620d6eb651fe.
  • SGLang source commit 2511743bd784e69e5a81ca3d926a000711dae4ab. The page says H3 support ships in SGLang v0.5.17 and later on PyPI, and that the diffusion install still uses --prerelease=allow. It also says H3 diffusion serving is not yet a stable SGLang release contract.
  • Download only the partition you will serve. For FL2VA that is model_index.json plus FL2VA/*. Keep the repository root as --model-path and select the partition with --model-variant fl2va. Do not point the server at the FL2VA/ subdirectory.
  • The quickstart hardware line is one node with 8× NVIDIA B200, Ulysses degree 8, and resident components. The page calls this a reference configuration, not a minimum.
  • Readiness is /health returning {"status":"ok"}. /liveness only means the HTTP process is up.

The model card's download for a single task family is:

hf download MiniMaxAI/MiniMax-H3 --include "model_index.json" "FL2VA/*" --local-dir MiniMax-H3

For an air-gapped machine, the deploy guide says to run that download on a connected computer, copy the directory, confirm model_index.json and the chosen FL2VA/ or Ref2VA/ directory are present, and start with HF_HUB_OFFLINE=1. The mainland China mirror MiniMax/MiniMax-H3 is mentioned, and the guide says revision parity with the pinned Hugging Face commit has not been documented, so the pinned baseline does not use it.

The model card also points at Diffusers and at a vLLM recipe. Diffusers is a loader for the same Hugging Face repository, not a second model. The vLLM-Omni section on MiniMax's deploy page is labeled experimental and community-maintained. Neither one turns the hosted Context-IR or 2K modules into local code.

If the published multi-GPU shape does not fit the computer you own, a rented machine is still remote hardware. The cloud GPU guide on this site is about planning a rental for image checkpoints. It does not add an H3 VRAM number, and a rental does not make H3-Context-IR or H3-Regenerate-2K local.

MiniMax H3 versus the hosted API

The useful comparison is the system boundary, not a quality ranking. This site has not run a side-by-side.

  • Hosted API or Hailuo app. You send the request to MiniMax. The full stack can include Context-IR and 2K regeneration. You do not install weights. Inference is not local.
  • Local H3-Base. You download FL2VA, Ref2VA, or both, and you run SGLang, vLLM, Diffusers, or the Comfy-Org conversion. Output stays in the 768p contract above unless you call the hosted 2K API afterward.
  • Comfy-Org weights versus the official checkpoint. Both can run on your machine. MiniMax says they are different artifacts. Do not mix their benchmark claims.

Image models already documented here are a different task, not a substitute checkpoint for H3. FLUX.1-dev, HiDream-O1-Image, Z-Image, Qwen-Image-Edit-2511, and HunyuanImage 3.0 generate or edit still images. They do not implement H3's fl2va audio-video task. No latency or preference score between those models and H3 is claimed here.

Prompt structure from the official skill

MiniMax ships a prompt-writing skill in the H3 repository. It is a format guide, not a measured quality score. For the base modes the skill says to keep three fields in this order: integrated_multimodal_description, overall_soundscape, then non_diegetic_music. The modes it names are:

  • T2VA: build the audiovisual timeline from text.
  • I2VA: start from the first frame and move forward.
  • FL2VA: describe a continuous path between the first and last frames.
  • L2VA: infer a plausible opening that lands on the supplied last frame.

Ref2VA is a separate six-part rewrite: subject_definitions, summary, retention_analysis, detailed_description, overall_soundscape, and non_diegetic_music. The skill says to write the rewrite in English, keep dialogue and on-screen text in their original language, match the description to the requested duration (4–15 seconds), and state how a keyframe connects to the timeline. The full templates are references/base-en.txt and references/ref-en.txt next to that skill. This page does not add prompts of its own.

First and last frame

FL2VA is the local checkpoint for that job. The model card says zero images means text-to-video, one image means a first-frame or last-frame condition, and two images mean first-and-last-frame generation. The deploy guide maps the same idea to SGLang task fl2va with one or two image conditions whose role is keyframe, and to the ComfyUI I2V template.

This site cannot run that generation. If you already have a clip and need the opening and closing images as files, the first and last frame video page extracts them in the browser. It does not call MiniMax.

MiniMax-H3-Image through the hosted API

MiniMax-H3-Image is the still-image model: text-to-image and image editing. It is not an H3-Base video checkpoint, and a call to the hosted image API is not local inference. The facts in this section were read on November 12, 2026 from MiniMax's API reference, pricing page, and the MiniMax-H3-Image model card. Google's image prices were read the same day from the Gemini pricing page.

Endpoint and API key

The model card names two hosts. Global requests use https://api.minimax.io. The China host in the same card is https://api.minimax.cn. Text-to-image is POST /v1/images/generations. Image editing, 1 to 16 reference images, is POST /v1/images/edits. Both accept MiniMax-H3-Image and MiniMax-H3-Image-Highspeed. The OpenAPI security scheme is Authorization: Bearer plus the API key.

MiniMax's preparation guide says to register or log in on the API platform, then open API Keys and choose “Create new secret key” for pay-as-you-go. That guide says pay-as-you-go covers image models. The key is a credential: the API FAQ says not to share it or put it in browser or other client-side code. Store it in an environment variable such as MINIMAX_API_KEY. M Plan uses a separate subscription key; do not treat the two keys as interchangeable. Pay-as-you-go charges the account balance. This site does not issue a MiniMax key and does not add credit to an account.

The generations reference says the server waits up to 600 seconds, so the client timeout should be at least that long. The endpoint is not idempotent: after the request is sent, MiniMax finishes generation and charges for successful images even if the client disconnects, and a retry generates and charges again.

A basic text-to-image request

The reference marks model and prompt as required. n defaults to 1. The body below uses the prompt and the 2720x1536 size from the documented example, with one image and a URL response. Replace nothing except the key, which should already be in the environment.

curl --max-time 600 https://api.minimax.io/v1/images/generations \
  -H "Authorization: Bearer $MINIMAX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "MiniMax-H3-Image",
    "prompt": "An orange cat lying on a windowsill basking in the sun, warm afternoon light, film texture",
    "size": "2720x1536",
    "n": 1,
    "response_format": "url"
  }'

For the China host, change the origin to https://api.minimax.cn and keep the same path. Download the image from the returned URL yourself; the reference says that URL is not guaranteed to remain available. Editing uses the other path and is documented separately.

Price: hosted API, local weights, and Nano Banana

MiniMax bills the hosted image API in tokens, and also publishes illustrative per-image totals. On the pricing overview, standard MiniMax-H3-Image is $2.30 per million input text tokens, $1.50 per million input image tokens, and $3.80 per million output image tokens. MiniMax-H3-Image-Highspeed is $2.30, $3.00, and $7.60 on those same three meters. The page says the per-image amounts are estimates for one image and can change with the text-token count, including tokens added by prompt enhancement.

The example table applies that note to the 4K rows. It is a dated offer, not the underlying token rate. A 4096×4096 image is 16,777,216 pixels, which meets the pixel test MiniMax wrote down; a 2048×2048 image does not.

Running the weights yourself does not have a dollar price on the model card or on that pricing page. The card lists the image repository at 68.65 GB, of which the DiT files are 66.28 GB and the image VAE is 2.34 GB, plus a 66.7 GB text encoder loaded from MiniMaxAI/MiniMax-H3 rather than from the image repository. An optional prompt expander is listed at 17.9 GB. Those are download sizes. MiniMax does not publish electricity, a GPU purchase price, or a local cost per image, and this page does not invent one. A rented GPU would be a third bill, from the rental provider, and it would still be remote hardware.

Google's Gemini API pricing, read the same day, prices Nano Banana by tokens as well, and it prints image-output equivalents that are not the same kind of total as MiniMax's examples. For standard gemini-nano-banana-2.1 (Nano Banana 2.1), the free tier is listed as not available. Input is $1.50 per million tokens for text, image, and video. Image output is $30 per million tokens, which the footnote equates to $0.0336 for a 1K image (1024×1024, 1120 tokens), $0.0504 for 2K (2048×2048, 1680 tokens), and $0.113 for 4K (4096×4096, 3780 tokens). Text and thinking output is a separate $7.50 per million tokens. The same footnote prices Batch image output at $15 per million tokens. Those per-image lines are image-output equivalents. Input tokens, and any search grounding, are extra.

Nano Banana 2, gemini-3.1-flash-image, is another row. Its standard image output is $60 per million tokens: the footnote equates that to $0.067 at 1K, $0.101 at 2K, and $0.151 at 4K, with input at $0.50 per million text or image tokens, and the free tier again listed as not available. The English overview on this site says Google recommends Nano Banana 2.1 for new projects, as checked on October 9, 2026. That is a model-selection note, not a statement that 2.1 costs the same as Nano Banana 2.

Do not subtract MiniMax's $0.02179 example from Google's $0.0336 image-output equivalent and call the difference a saving. One figure is MiniMax's illustrative total for a sample prompt. The other is Google's image-output token price before input. Use the vendor page for the exact model ID, resolution, and prompt you will send.
