如何在本地运行 MiniMax H3

MiniMax H3 可以是你自己机器上的开源 H3-Base 视频权重，也可以是 MiniMax 的托管 API。这是两套系统。下面的硬件说明只谈视频这条边界。后文单独写静图模型 MiniMax-H3-Image 的托管接口。本站没有对两者做过基准测试。

nano-banana.live 不是 MiniMax 的网站，不分发 H3 权重，也没有测过 H3。下面的数字转录自 MiniMax 的模型卡、仓库和本地部署指南，2026 年 10 月 22 日重读。部署指南自己写的最后审阅日期是 2026 年 8 月 26 日。买硬件或钉死某个 commit 之前，请再打开那些页面看一遍。

本地客户端不等于本地推理

MiniMax-H3 模型卡列出两种使用完整产品的托管方式：Open Platform API（全球用 platform.minimax.io，中国用 platform.minimaxi.com），以及 Hailuo 应用（hailuoai.video 和 hailuoai.com）。笔记本上的 Python 脚本去调这些地址，只是客户端。模型仍跑在 MiniMax 的服务上。

真正的本地推理，是开源权重在你控制的机器上执行。同一张模型卡说，完整的 H3 系统有三个模块，开源发布里只有其中一个：

  • H3-Context-IR 把自由形式的多模态指令收成结构化表示。MiniMax 说它依赖托管模型，不在开源发布里。
  • H3-Base 生成 768p 视频，并带同步立体声。这是你可以下载的部分。
  • H3-Regenerate-2K 用 768p 输出和原始上下文再生成 2K 结果。MiniMax 说这个模块尚未开源。模型卡上的「2K」指的是这一步托管处理，不是本地 checkpoint 上的一个开关。

MiniMax 的本地部署指南把后果写得很直接：自建的 H3-Base 服务复现不了平台上完整的 Context-IR 和 2K 流程。模型卡上的「完整 2K 工作流」是本地 SGLang 进程再加上那两个托管 API。这种混用不是离线。

开源发布里有什么

模型卡和 MiniMax-H3 仓库描述了两个任务 checkpoint。两者都是经过 CFG 蒸馏的 Omni Transformer 权重，随附 processor、tokenizer、文本编码器、视觉 VAE 和音频 VAE。

Checkpoint任务输入输出
H3-Base FL2VA t2va 文生音视频，以及 fl2va 首尾帧生音视频 文本。可选首帧、尾帧，或两者都给。 视频和音频，BF16
H3-Base Ref2VA ref2va 参考生音视频 文本，加上参考图像、视频和/或音频。模型卡的上限是 9 张图、3 段视频、3 段音频，合计最多 12 个文件。每段 2–15 秒，每种模态的总时长最多 15 秒。 视频和音频，BF16

同一天核对的输出约定是：4–15 秒，短边默认 768 像素，24 FPS，32 kHz 立体声。点名的宽高比包括 21:9、16:9、4:3、1:1、3:4 和 9:16。对白稳定支持阿拉伯语、中文、英语、法语、德语、意大利语、日语、韩语、葡萄牙语、俄语和西班牙语。FL2VA 和 Ref2VA 不能互换：部署指南说，FL2VA 服务不会提供 ref2va。

架构上，模型卡说 H3-Omni-Transformer 是 330 亿参数的稠密模型，其中约 130 亿在 AdaLN 分支里，只做推理时不必加载。文本编码器使用完整的 Qwen3-VL-32B 权重，读取第 50 层的隐藏状态。这些是参数量，不是测出来的显存下限。

权重使用 MiniMax H3 Community License Agreement。模型卡和仓库里的许可文本，才是地域、商用和可接受用途的依据。本页不转述那些条款。

怎样在本地运行 MiniMax H3

模型卡点了四个推理框架，各自有指南：SGLang、vLLM、Diffusers 和 ComfyUI。MiniMax 的部署指南最后审阅于 2026 年 8 月 26 日，分成可视化的 ComfyUI 路径，和钉死版本的 SGLang 服务。它把 vLLM-Omni 配方视为社区维护，而不是该页可复现的基线。

工作站上的 ComfyUI

这是部署指南为交互式本地使用推荐的路径。它仍然只对 ComfyUI 下载的转换后权重做本地推理。文件来自 Comfy-Org/MiniMax-H3，包括 INT8 和 NVFP4 组件。MiniMax 说它们和官方的混合 BF16/FP32 checkpoint 不是同一套数值基线，显存和画质都可以不同。

指南审阅过的基线是 ComfyUI 0.30.0 或更新版本，内置 T2V、I2V 和 R2V 模板。它也说，这份 ComfyUI 指南没有公布最低显存。列出的步骤是：

  1. 把 ComfyUI 更新到 0.30.0 或更新，然后启动。
  2. 打开 Template Library，再打开 Video。
  3. 选择 MiniMax H3 的 T2V、I2V 或 R2V。T2V 和 I2V 用 FL2VA 扩散模型。R2V 用单独的 Ref2VA 模型。
  4. 让模型扫描弹窗下载模板要求的文件。模型列表没刷新就重启 ComfyUI。
  5. 填写提示词，以及需要的图像、视频或音频参考。I2V 接收一张输入图，可选首帧和尾帧。
  6. 在 Resolution Selector 里用 0.98 兆像素，边长为 32 的倍数，或直接设 1344×768。指南说不要用 1.0 兆像素那一档，因为它会落到 1376×768，超过 H3-Base 768×1344 的像素面积上限。
  7. 把工作流加入队列。文档中的结果是一段 MP4：24 FPS 视频流，加上同步立体声。

时长会吸附到模型在 24 FPS 下的 17k + 5 帧网格，所以你填的长度可能被挪到合法帧数。示例 FL2VA 工作流用 20 步，另有可选的 8 步 Turbo LoRA，指南说它可能降低动作和音频质量。对比输出时把 LoRA 记下来。

用 SGLang 自建 API

模型卡上的 FL2VA 短示例是一条四卡启动命令。它没有写 GPU 型号：

sglang serve \
  --model-path MiniMaxAI/MiniMax-H3 \
  --num-gpus 4 \
  --ulysses-degree 4 \
  --performance-mode speed \
  --host 0.0.0.0 \
  --port 30010 \
  --model-variant fl2va

这个 host 参数要看仔细。部署指南钉死的快速开始绑定的是 127.0.0.1，并且说，在把绑定改成 0.0.0.0 之前，要先在端口前面放上认证、TLS、配额，以及许可证要求的托管服务防护。把模型卡上的命令直接暴露到公网，不是指南的基线。

同一份指南可复现的基线（审阅于 2026 年 8 月 26 日）比「装上 SGLang 就能跑」窄得多：

  • 模型 MiniMaxAI/MiniMax-H3，修订 42ed227ee7df40d41602854ae760620d6eb651fe。
  • SGLang 源码提交 2511743bd784e69e5a81ca3d926a000711dae4ab。该页说 H3 支持从 SGLang v0.5.17 起随 PyPI 提供，扩散安装仍要加 --prerelease=allow。它也说，H3 扩散服务还不是稳定的 SGLang 发布契约。
  • 只下载你要服务的那一份。FL2VA 是 model_index.json 加上 FL2VA/*。--model-path 保持仓库根目录，用 --model-variant fl2va 选择分区。不要把服务器指到 FL2VA/ 子目录。
  • 快速开始的硬件一行是：单机 8 张 NVIDIA B200，Ulysses 度数 8，组件常驻。该页称这是参考配置，不是最低配置。
  • 就绪的标志是 /health 返回 {"status":"ok"}。/liveness 只说明 HTTP 进程活着。

模型卡上单个任务族的下载命令是：

hf download MiniMaxAI/MiniMax-H3 --include "model_index.json" "FL2VA/*" --local-dir MiniMax-H3

对完全离线的机器，部署指南说：在能联网的电脑上下载，拷贝目录，确认 model_index.json 和所选的 FL2VA/ 或 Ref2VA/ 都在，再用 HF_HUB_OFFLINE=1 启动。文中提到中国大陆镜像 MiniMax/MiniMax-H3，并说它和钉死的 Hugging Face 提交是否修订一致尚未记录，所以钉死的基线不用这个镜像。

模型卡也指向 Diffusers 和一份 vLLM 配方。Diffusers 是同一套 Hugging Face 仓库的加载器，不是第二个模型。MiniMax 部署页上的 vLLM-Omni 一节标为实验性、由社区维护。两者都不会把托管的 Context-IR 或 2K 模块变成本地代码。

2026 年 10 月 22 日读过的材料里，没有单一的「最低电脑配置」。部署指南说，没有公布的要求，不等于没有要求。用和你实际安装路径对应的那一行。

如果公布的多卡形态装不进你现有的电脑，租来的机器仍然是远程硬件。本站的云 GPU 指南谈的是为图像 checkpoint 规划租赁。它没有补上一个 H3 显存数字，租赁也不会让 H3-Context-IR 或 H3-Regenerate-2K 变成本地的。

MiniMax H3 和托管 API

有用的比较是系统边界，不是质量排行。本站没有做过并排测试。

  • 托管 API 或 Hailuo 应用。请求发给 MiniMax。完整栈可以包含 Context-IR 和 2K 再生。你不安装权重。推理不在本地。
  • 本地 H3-Base。你下载 FL2VA、Ref2VA 或两者，用 SGLang、vLLM、Diffusers，或 Comfy-Org 的转换权重来跑。除非事后再调托管的 2K API，输出停在上面的 768p 约定里。
  • Comfy-Org 权重和官方 checkpoint。两者都可以在你的机器上跑。MiniMax 说它们是不同产物。不要把两边的基准数字混在一起。

本站已经写过的图像模型是另一项任务，不能当作 H3 的替代 checkpoint。FLUX.1-dev、HiDream-O1-Image、Z-Image、Qwen-Image-Edit-2511 和 HunyuanImage 3.0 生成或编辑静图。它们不实现 H3 的 fl2va 音视频任务。这里不声称这些模型和 H3 之间的延迟或偏好分数。这些指南目前是英文。

官方 skill 里的提示词结构

MiniMax 在 H3 仓库里放了一份写提示词的 skill。它是格式指南，不是测出来的质量分。对基础模式，skill 要求按这个顺序保留三个字段：integrated_multimodal_description、overall_soundscape，然后是 non_diegetic_music。它点名的模式是：

  • T2VA：从文本搭出视听时间线。
  • I2VA：从首帧出发往前走。
  • FL2VA：描述首帧和尾帧之间的连续路径。
  • L2VA：推断一个合理的开场，落到给定的尾帧上。

Ref2VA 是另一套六段改写：subject_definitions、summary、retention_analysis、detailed_description、overall_soundscape 和 non_diegetic_music。skill 说改写用英文写，对白和画面文字保留原文，描述要匹配所请求的时长（4–15 秒），并写明关键帧怎样接到时间线上。完整模板是该 skill 旁边的 references/base-en.txt 和 references/ref-en.txt。本页不另加提示词。

首帧和尾帧

FL2VA 是做这件事的本地 checkpoint。模型卡说：零张图是文生视频，一张图是首帧或尾帧条件，两张图是首尾帧生成。部署指南把同一件事映射到 SGLang 任务 fl2va，一到两个角色为 keyframe 的图像条件，以及 ComfyUI 的 I2V 模板。

本站跑不了这次生成。如果你已经有一段片子，只需要把头尾存成图片文件，首尾帧视频页面在浏览器里提取。它不调用 MiniMax。该页目前是英文。

通过托管 API 使用 MiniMax-H3-Image

MiniMax-H3-Image 是静图模型：文生图和图像编辑。它不是 H3-Base 视频 checkpoint，调用托管图像 API 也不是本地推理。这一节的事实在 2026 年 11 月 12 日读自 MiniMax 的 API 参考、定价页，以及 MiniMax-H3-Image 模型卡。Google 的图像价格同一天读自 Gemini 定价页。

端点和 API 密钥

模型卡写了两个主机。全球请求用 https://api.minimax.io。同一张卡上的中国主机是 https://api.minimax.cn。文生图是 POST /v1/images/generations。图像编辑（1 到 16 张参考图）是 POST /v1/images/edits。两者都接受 MiniMax-H3-Image 和 MiniMax-H3-Image-Highspeed。OpenAPI 的安全方案是 Authorization: Bearer 加上 API 密钥。

MiniMax 的准备指南说，先在 API 平台注册或登录，再打开 API Keys，为按量计费选择 “Create new secret key”。该指南说按量计费覆盖图像模型。密钥是凭证：API FAQ说不要分享它，也不要放进浏览器或其他客户端代码。把它放在环境变量里，例如 MINIMAX_API_KEY。M Plan 用另一把订阅密钥，不要把两把钥匙当成可以互换。按量计费从账户余额扣款。本站不签发 MiniMax 密钥，也不给账户充值。

生成接口的参考说服务器最多等 600 秒，所以客户端超时至少要这么长。这个端点不是幂等的：请求发出之后，即使客户端断开，MiniMax 仍会做完生成，并对成功的图像收费；重试会再生成一次、再收一次费。

一次基本的文生图请求

参考把 model 和 prompt 标为必填。n 默认是 1。下面的请求体用文档示例里的提示词和 2720x1536 尺寸，一张图，响应为 URL。除了已经在环境里的密钥，不要替换别的内容。

curl --max-time 600 https://api.minimax.io/v1/images/generations \
  -H "Authorization: Bearer $MINIMAX_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "MiniMax-H3-Image",
    "prompt": "An orange cat lying on a windowsill basking in the sun, warm afternoon light, film texture",
    "size": "2720x1536",
    "n": 1,
    "response_format": "url"
  }'

中国主机把源换成 https://api.minimax.cn，路径不变。图像 URL 要自己下载；参考说这个 URL 不保证一直可用。编辑走另一条路径，文档是分开的。

价格：托管 API、本地权重和 Nano Banana

MiniMax 按 token 给托管图像 API 计费，同时也公布了示意性的单张总价。在定价概览上，标准 MiniMax-H3-Image 是每百万输入文本 token 2.30 美元、每百万输入图像 token 1.50 美元、每百万输出图像 token 3.80 美元。MiniMax-H3-Image-Highspeed 在同样三项上是 2.30、3.00 和 7.60 美元。该页说，单张金额是一张图的估计，会随文本 token 数量变化，包括提示词增强加进去的 token。

自己跑权重，在模型卡和那张定价页上都没有一个美元单价。模型卡列出图像仓库 68.65 GB，其中 DiT 文件 66.28 GB，图像 VAE 2.34 GB，另外还要从 MiniMaxAI/MiniMax-H3 而不是图像仓库加载 66.7 GB 的文本编码器。可选的提示词扩展器列为 17.9 GB。这些是下载体积。MiniMax 没有公布电费、显卡购买价或本地的单张成本，本页也不编一个。租来的 GPU 是第三张账单，由租赁商开，而且仍然是远程硬件。

Google 的 Gemini API 定价同一天阅读，Nano Banana 同样按 token 计价，并印出图像输出的等价金额。那和 MiniMax 示例里的合计不是同一种数。标准 gemini-nano-banana-2.1（Nano Banana 2.1）的免费层标为不可用。文本、图像和视频输入是每百万 token 1.50 美元。图像输出是每百万 token 30 美元，脚注把它换算成 1K 图像 0.0336 美元（1024×1024，1120 token）、2K 0.0504 美元（2048×2048，1680 token）、4K 0.113 美元（4096×4096，3780 token）。文本和思考输出另按每百万 token 7.50 美元计。同一脚注把 Batch 图像输出标为每百万 token 15 美元。这些单张数字是图像输出的等价额。输入 token，以及任何搜索接地，都另算。

Nano Banana 2，即 gemini-3.1-flash-image，是另一行。它的标准图像输出是每百万 token 60 美元：脚注换算为 1K 0.067 美元、2K 0.101 美元、4K 0.151 美元，文本或图像输入为每百万 token 0.50 美元，免费层同样标为不可用。本站英文概览说，截至 2026 年 10 月 9 日的核对，Google 建议新项目用 Nano Banana 2.1。这是选型说明，不是说 2.1 和 Nano Banana 2 同价。

不要用 MiniMax 的 0.02179 美元示例去减 Google 的 0.0336 美元图像输出口径，然后把差额叫作省下来的钱。一个是 MiniMax 对示例提示词的示意合计。另一个是 Google 在计入输入之前的图像输出 token 价格。确切的模型 ID、分辨率和你要发送的提示词，以厂商页面为准。
